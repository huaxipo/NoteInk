# 墨记 NoteInk

一个原生 Android 手写笔记应用，对标 Notein 的核心体验：导入各种文件、在页面上直接手写批注、多色多笔型、纯本地存储。

## 安装

| 文件 | 说明 |
|---|---|
| [NoteInk-1.5.2.apk](https://github.com/huaxipo/NoteInk/releases/latest) | **推荐**。release 版，已签名，可直接安装 |
| NoteInk-1.5.2-debug.apk | 调试版，保留调试信息，在同一个 Release 页面的 Assets 中 |

安装包不打进 git 历史（每个 6~9MB，会让 clone 变得很慢），统一放在
[Releases](https://github.com/huaxipo/NoteInk/releases) 页面。

从旧版直接覆盖安装即可升级，笔记数据保留（同包名、同签名）。
装好后**书架标题下方会显示 `v1.5.2`**，可用来确认装的是哪一版。

> 1.2.1 起导入方式有变化（源文件会额外保留一份、文本页存 PNG），1.3.0 起 PPT 也会保留源文件。
> 1.4.1 起**旧笔记本会自动重画底图**（保留笔迹），不用再删掉重导入。

- 最低系统：**Android 8.0（API 26）**，目标 API 34
- 包名：`com.noteink.app`
- 签名：使用本地 debug keystore 自签名，仅供个人安装，不能上架应用商店
- 手机上点开 APK 安装时，需要允许「安装未知来源应用」

## 从源码构建

需要 JDK 17 与 Android SDK（API 34）。仓库自带 Gradle Wrapper：

```bash
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

Windows 上用 `gradlew.bat`。若本机已把 JDK / SDK 放在特定位置，也可以直接改 `build.bat`
里的 `JAVA_HOME` 与 `ANDROID_HOME` 再运行 `build.bat assembleRelease`。

首次构建会通过阿里云镜像与官方源拉依赖，约需几分钟。

## 功能

**导入**（新建笔记本时点「导入文件」）
- PDF —— 整份导入，每页照原样栅格化，可直接在页面上批注
- 图片 PNG / JPG / WEBP —— 自动矫正 EXIF 旋转，超宽图自动降采样
- Word `.docx` —— **本地保真排版**：段落对齐、段前段后距、首行缩进、粗体/斜体/字号/文字颜色、标题样式（Title / Heading 1–3）、内嵌图片、表格网格；放不下自动分页
- PowerPoint `.pptx` —— **按形状真实坐标还原**：文本框位置/字号/颜色/对齐、图片按原位摆放、表格转网格；整页预览图会直接当整页用（避免文字重影）
- TXT / Markdown —— 自动识别 UTF-8 / GBK；Markdown 会去掉语法符号保留正文
- Office 解析失败时自动回退到「抽取文字重排」，保证不会整个导入失败

**导出与备份**
- 单页导出 PNG（1200 万像素以内 1:1 输出）
- 整本导出 PDF（A4 比例，矢量笔迹，可打印）
- 整本打包为 `.zip` 备份（含底图与笔迹），书架右上角「恢复备份」可还原成一个新笔记本
- 全部走系统文件选择器，不申请存储权限

**手写**
- 7 种工具：钢笔、铅笔、马克笔、荧光笔、橡皮、套索、**圈擦**（圈住即删）
- **矢量渲染**：笔迹不再缓存成整页位图，按当前缩放直接绘制路径，放大 18 倍依然清晰
- 压感笔迹：真实压力优先；设备不上报压力时按**书写速度模拟**（快细慢粗），可开关
- 20 色墨水池 + 6 色荧光池 + HSV 自定义取色（色相/饱和/明度三滑杆）
- 铅笔半透明、马克笔粗实、荧光笔低透明度叠加
- 橡皮两种模式：**整笔擦除**（默认，快）与**局部擦除**（像真橡皮，只挖掉一段），工具栏可切
- 套索圈选后可拖动移动、批量删除；**圈擦**画一个圈，圈到的笔**整笔删除**（一步撤销）
- 撤销 / 重做（命令栈，含加笔、局部擦除、移动、删页），保留最近 200 步
- 删除整页后底部弹出「撤销」浮条，5 秒内可恢复
- 双指缩放平移，`适配屏幕` 一键归位

**存储**
- 全部在应用私有目录，不联网、无权限申请
- 笔迹用 gzip 二进制编码（一笔 200 点约 1KB），自动保存（停笔 0.8s 落盘），切后台也保存
- 笔记本封面缩略图自动生成

## 1.1.1 更新（顶栏不可见的问题）

真机上出现「看不到撤销和退出键」，实测截图像素后确认：编辑器的顶栏整条高度为 0，画布直接顶到状态栏下方，所以返回 / 撤销 / 重做 / 更多全都被挤没了。

修法不是调图标，而是改结构：

- **顶栏改为固定高度 52dp + 覆盖层绘制**。之前是靠 `Surface` 内的 `Row` 撑开高度，一旦原生画布视图（`AndroidView`）的布局尺寸异常，整条栏就会被挤成 0 或被画布盖住。现在顶栏作为 `Box` 的独立子项、在 `Column` 之后绘制，高度写死，物理上不可能再塌陷。
- **撤销 / 重做同时放到底部胶囊**（`↶  2/85  ↷`），离手指更近，也不依赖顶栏 —— 即使顶栏还有问题也一定能用。
- 顺手修掉一个渲染问题：`onSizeChanged` 里原来只在首次布局时 `fitToPage()`，之后旋转屏幕或工具栏高度变化都不会重新居中，页面会停在偏下 50px 左右的位置。现在只要用户没手动缩放/平移，尺寸变化就重新适配。

## 1.1.0 更新

**撤销**
- 顶栏撤销 / 重做改用自绘图标（原来用 `↶ ↷` 字符，部分机型字体缺字会显示成方块或空白），触控区从 38dp 放大到 44dp，点击有振动反馈
- 历史栈上限 200 步，超出丢弃最旧的，长笔记不会无限吃内存
- 删除整页新增撤销：页面只从列表摘除、文件保留，5 秒内可恢复；超时或退出后才真正清理

**返回主页**
- 修掉一个会丢笔迹的 bug：原来退出时的保存挂在界面作用域上，界面一销毁协程就被取消，`writeCover` 和最后一笔可能没写完。现在保存挂在 `MainActivity` 的应用级作用域上，界面销毁也能写完
- 落盘改为串行（互斥锁），避免自动保存和退出保存同时写同一个文件而损坏
- 退出时元信息同步写盘，回到列表页立刻能看到最新页数和时间

**导入速度**
- 页面底图从 PNG(q100) 改为 JPEG(q90)：同样一页 A4 的编码耗时大约从 300–600ms 降到 50–90ms
- 编码写盘与「渲染下一页」并行流水线（2 张在途），PDF 渲染仍是串行（PdfRenderer 限制）但编码不再阻塞
- 信号量控制内存中同时存在的页面位图不超过 2 张，几百页的 PDF 也不会 OOM
- 导入过程显示「已完成 / 总页数」，长文档不再像卡死
- 多文件导入显示 `(2/3)` 进度


## 1.2.0 更新

**1. 高倍缩放清晰度 —— 改为矢量直绘**

原来笔迹提交后被缓存成一张整页位图（A4 约 1240×1754），放大 3 倍以上必然发虚。现在完全去掉这张缓存，每一帧都按当前缩放直接绘制路径，并配套三件事保证不掉帧：

- 每笔的外形路径缓存在 `Stroke` 上，几何不变时零重建
- 视口裁剪：只画与可见区域相交的笔迹，放大后大部分笔不参与绘制
- 包围盒单独缓存，裁剪判定不必遍历点

顺带的好处是每页省掉约 8.7MB 的位图内存。

**2. Office 本地保真**

- DOCX：用 XmlPullParser 逐段解析，`w:pPr` 里的对齐 / 段距 / 首行缩进、`w:rPr` 里的粗体 / 斜体 / 字号 / 颜色全部还原；标题样式（Title、Heading 1–3）做了映射，否则 Word 里靠样式定义的标题会退化成正文大小；内嵌图片按 EMU 尺寸换算成页面像素；表格按等宽列 + 细边框渲染
- PPTX：按形状的 `a:xfrm` 真实坐标和尺寸摆放文本框与图片，字号由 `sz/100`（pt）换算，表格转网格
- 换行统一交给系统的 `StaticLayout`，段内样式用 `Spannable` 承载，所以中文断行、行高都是系统级正确的
- 实测发现部分导出工具会把整张幻灯片先渲染成一张图塞回 pptx（`descr="Image preview"` / `bg_cover.png`），同时又保留各个文本框。这种整页图会直接被当成整页使用、跳过其它形状，否则文字会和图上的字重影

**3. 像素级橡皮**

- 默认仍是**整笔擦除**（快，符合"擦掉一个字"的习惯）
- 底部工具栏切到「局部」后，橡皮轨迹会作为一条擦除笔画存入笔迹流，渲染时整段笔迹画进离屏图层，橡皮用 `CLEAR` 混合挖洞 —— 只挖掉墨，不会擦穿背景
- 离屏图层只覆盖可视区域，否则高倍缩放下按整页尺寸分配会上百 MB
- 轨迹实时可见（拖动时就能看到挖除效果），撤销即整条轨迹回退

**4. 压感增强**

- 自动识别：只要有一笔上报了非 1.0 的压力，就判定为真实压感笔，全程用真实值
- 否则按书写速度反推线宽：0 px/s → 最粗，2400 px/s 以上 → 最细，用指数滑动平均抹掉抖动
- 「更多」里可关闭压感模拟，改成等宽

**5. 导出与备份**

- 单页 PNG、整本 PDF（A4 比例 595×842pt，矢量笔迹）、整本 `.zip` 备份
- 恢复备份会新建一个笔记本，不覆盖已有笔记
- 全部走 SAF 文件选择器，不申请任何存储权限

## 1.5.2 更新（修掉两处「信息不完整」）

导入某些 PPTX 时，页面会少一整块内容、底部一行字还会被裁掉首字。两个独立的原因：

**1. 左对齐文本被往左推了 15% 框宽**

`wrap="none"` 的文本框（PowerPoint 导出的演示稿几乎全是这种）为了防折行会把布局宽度
撑到 `1.3 × 框宽`。原先对所有形状都做一次「居中补偿」——把布局中心拉回形状框内，
可左对齐文字根本不需要补偿，结果整段往左偏 `(1.3w - w)/2`。

在 1654px 的底图上，底部横幅偏了约 126px：「竞品可以抄走…」的「竞」被推出页外；
三段标题左移后正好压住前面的 `01` / `02` / `03`，编号也看不见了。现在只有居中、
右对齐才做补偿，左对齐保持形状本身的 x。

**2. SVG 内嵌图形的引用没被读到**

PowerPoint 2016 之后常把矢量图形存成 `asvg:svgBlip`，引用藏在
`a:blip/a:extLst` 里，外层 `<a:blip>` 可能连 `r:embed` 都没有，也不提供 PNG 回退图。
渲染器只按 `r:embed` 取图，于是整张图消失——四个圆圈和虚线环就是这样没的。

现在把 `svgBlip` 的 rId 提到外层，再用内置的一个极简 SVG 光栅器把
circle / ellipse / rect / line（含描边与虚线）画成位图，不引入任何三方库。
外层本来就有 PNG 回退图时仍优先用位图。

`RENDER_VERSION` 升到 12，旧笔记本打开时会自动重画底图，笔迹保留。

## 1.5.1 更新（关掉系统自动备份）

`AndroidManifest.xml` 里的 `android:allowBackup` 从 `true` 改成了 `false`。

原来这个开关是默认值 `true`，系统会把 `filesDir` 下的笔记库自动同步到 Google Drive（装了
Google 备份服务的机器上）。这和「纯本地存储」的承诺是矛盾的——笔记虽然写在私有目录里，
却仍然被上传了一份。现在关闭后，应用数据只存在于本机，卸载即消失。

功能上没有变化，手写、导入、导出、备份 zip 全部照旧。

## 1.5.0 更新（花括号画成了方角：切线方向反了 90°）

文字已经排成列，剩下的问题是**花括号的弧画歪了**：钩不像圆弧，像被折了一下的方角，
中间的尖也偏钝。

根因是二次贝塞尔的控制点选错。原来两段钩都写成

```kotlin
out.moveTo(1f, 0f)
out.quadTo(1f, ry, 0.5f, ry)      // 控制点放在正下方
```

控制点 (1, ry) 在起点的**正下方**，于是曲线在右上角是「先垂直向下、再拐成水平向左」。
而 PowerPoint 画的是反过来的：**先水平向左，再拐成垂直向下**。
两者的差别看起来只是直角的方向，但 1654px 的画布上，钩只有十几像素高，
这 90° 的偏差足以让它看着像折角而不是圆弧。

现在换成标准 1/4 椭圆弧的三次贝塞尔近似（`k = 0.5523`）。椭圆中心落在形状框**外面**
（右侧下方），只取框内那一段，切线方向自然就对上了：

```
上钩  (1,0) → (0.5,ry)   C1=(1-0.276, 0)      C2=(0.5, 0.448·ry)
尖上  (0.5,m-ry) → (0,m) C1=(0.5, m-0.448ry)  C2=(0.276, m)
尖下  (0,m) → (0.5,m+ry) C1=(0.276, m)        C2=(0.5, m+0.448ry)
下钩  (0.5,1-ry) → (1,1) C1=(0.5, 1-0.448ry)  C2=(1-0.276, 1)
```

顺带把 `[` `]` 的镜像也理顺了：`gx(0)` 现在恒为「开口那一侧」，`gx(1)` 恒为「钩那一侧」。

### 这次是怎么验证的

前几轮一直靠截图目测，越修越偏。这一版改用**权威渲染 + 像素叠加**：

1. 用 PowerPoint 的 COM 接口把第 13 页导出成 1654×932 的 PNG（与 App 底图同尺寸）；
2. 把新算法按真实 EMU 参数画成红线，叠到这张图上；
3. 放大 5 倍看——红线与 PowerPoint 的黑线**几乎完全重合**，钩、竖干、尖、
   下钩全部贴合，只有尖的末端差 1~2px。

样张与对照图不随仓库分发（它们来自第三方课件），验证在本地完成。

顺带记录实测数据（AutoShape 4，31×254 px，adj1=50249）：PowerPoint 的钩高 14px、
横向 15.5px，中间尖纵向跨度 28px——与公式 `y1 = min(w,h)·adj1/100000` 算出的
15.6px 一致，说明半径公式本来就是对的，错的只是曲线的切线方向。

## 1.4.9 更新（制表位改成定宽垫片；花括号按 OOXML 公式重画）

第 2 章第 13 页那张 C++ 数据类型树，1.4.8 之后文字**还是没排成列**：几行本该同一列的
文字左边缘参差不齐，花括号也仍然是「一根竖线加两个小勾」。两个独立的毛病：

**一、制表位宽度不该由字体反算。**

1.4.8 是「插入一个 NBSP，再用 `ScaleXSpan` 把它拉到目标宽度」，拉伸倍数 =
`需要的宽度 / measureText(NBSP)`。基准宽度只要偏一点，整列就跟着偏，而且误差逐格累积。
现在换成 `ReplacementSpan`：`getSize()` 直接返回像素宽度，画的时候什么都不画。
第 k 个制表位恒在 `k × 0.82 英寸` 上，与字体、与前面文字量出来多宽都无关 ——
垫片负责把笔位「顶回」准确位置，误差不累积。

顺带把制表位间距从「2.75 个字宽」改成绝对长度 **0.82 英寸**（`DEFAULT_TAB_EMU`）。
这个数是拿这一页五组花括号的位置反解出来的：6 个制表位落在 3.09 / 3.91 / 4.73 /
5.55 / 6.37 / 7.19 英寸，而花括号分别在 3.92~4.16、5.81~6.06、7.06~7.19 三处。

还有一条规则上的修正：制表位按 `lIns` 起算，而正文被 `marL` 缩进过一段，所以
「布局坐标里的第 k 格」= `k*tabPx - marL`，`tabOff` 就是 `-marL`。

**二、花括号被钳得太狠。**

上一版把 `adj1` 硬钳到 12500（那是圆角矩形的上限），但 OOXML 里花括号的上限是

```
maxAdj1 = min(100000-a2, a2)/2 × h/ss        ss = min(w,h)
```

细长的 `{` 这个上限非常大，`adj1="79242"` 完全合法。钳到 12500 后弧高只剩 0.03 英寸，
`{` 就退化成一条竖线。另外竖干位置也错了 —— OOXML 里头那两段弧是把整个宽度用满的
四分之一椭圆，竖干在**正中**（0.5），上一版放在 `1-弧半径` 处，宽度只用掉 12%。

改完的效果：`数据类型 ⟩ 基本类型 ⟩ 类型名 ⟩ 叶子`，四列分明，每组左侧都有对应的
`{`；`长双精度型(long double)` 仍在框内不折行。

## 1.4.8 更新（1.4.7 的制表位算错了：空格宽度不可靠）

1.4.7 已经认出这张树状图是「文本框 + `\t`」，但展开方式选错了：
用「算出要几个空格、拼一串空格」来补齐制表位。

```kotlin
val spaceW = tp.measureText(" ").coerceAtLeast(1f)
val cnt = ((target - curX) / spaceW).toInt()
```

问题有两层：

1. **`measureText(" ")` 在部分环境直接返回 0**（Robolectric 的 legacy 图形栈就是），
   被 `coerceAtLeast(1f)` 兜成 1px 之后，85px 的制表位被算出 **85 个空格**，
   一行光缩进就几千像素，直接撑爆折行 —— 比不展开还乱。
2. **空格宽度本身不可靠**。同一个 18pt，宋体半角空格、Roboto 空格、各家 ROM
   改过的默认字体之间能差一倍以上，缩进量跟着漂。

改成「一个字符 + 拉伸」：每个制表位插入**一个不换行空格** `U+00A0`，
再用 `ScaleXSpan` 把它拉到**精确的像素宽度**。单个字符拉伸不受任何字体影响，
算多少就是多少。

**制表位间距也从 2 个字宽改成 2.75 个**。2em 时 5 个 `\t` 只有 310px，
整棵树的节点仍然落在第一个花括号左边；2.75em 换成 427px，正好铺到三列花括号
（486 / 720 / 875）之间，与 WPS 的渲染对上。

**同时补上形状自己的 `<p:txBody><a:lstStyle>`**。以前只有版式（slideLayout）
里的 lstStyle 被读，文本框自己写的字号一律忽略、按 18pt 兜底。第 13 页
`Rectangle 2` 的 lstStyle 写的是 `sz="2800"`，被当成 18pt 之后，靠字宽算出来的
制表位跟着缩水三分之一。

> 这一页的 run 里其实还显式写了 `sz="1800"`，所以最终仍是 18pt —— 但「文本框
> 自己的 lstStyle 从来没被读」是个普遍缺陷（几乎所有普通文本框的字号都写在这一层），
> 顺手补掉。

## 1.4.7 更新（树状图：`\t` 制表位丢失 + 花括号 adj1 越界）

第 2 章第 13 页「C++的数据类型」那张树状图，在 WPS 里是一棵完整的树，
装进墨记后所有文字挤到最左边，只剩几个花括号孤零零挂在半空。

拆开 `slide13.xml` 才发现，**这张图里既没有 SmartArt，也没有连接线和组合**，
整页只有 8 个形状：

```xml
<p:sp> Rectangle 2   x=1993131 y=1196752 cx=8076611 cy=5483904   ← 一个大文本框
<p:sp> AutoShape 3~7 prst="leftBrace"                             ← 5 个左花括号
```

树的分支全靠作者在一个文本框里敲 `\t` 对齐出来的：

```
\t\t\t\t\t整型\t整型(int) 4
\t\t\t\t\t\t长整型(long int)4/8
\t\t\t\t\t浮点型\t双精度型(double)8
```

**根因一：`\t` 被吞掉。** Android 的 `StaticLayout` 对制表符只留一个极窄的空白，
等于把每段的缩进整段丢掉，17 行文字就全部贴到了框左边。WPS / PowerPoint 会把
`\t` 解释成「跳到下一个制表位」，而 PPTX 里没有制表位的列定义，只有一个默认间隔。

修法：`expandTabs()` 在排版前把 `\t` 换成空格 —— 逐字累计当前行宽度，遇到 `\t`
就跳到下一个「2 个字宽」的制表位补齐，字号取该位置 `AbsoluteSizeSpan` 的值
（大小字混排时缩进不会被算歪）。第 13 页实测缩进 410px / 246px / 82px，
正好落在 5 / 3 / 1 个制表位上。

**根因二：花括号的 `adj1` 没钳位。** 这几处的写法是

```xml
<a:prstGeom prst="leftBrace">
  <a:avLst><a:gd name="adj1" fmla="val 79242"/><a:gd name="adj2" fmla="val 50000"/></a:avLst>
</a:prstGeom>
```

`adj1=79242` 是远超上限的脏值。OOXML 的规则是
`a1 = pin(0, adj1, ((100000-adj2)/2+1)/2)`，即上限只有 12500；老代码既没钳位，
又把除数写成了 200000，结果圆弧半径算大了 3 倍多，细长的 `{` 胖成一个圆弧。
现在按规范钳位、除数改回 100000。

> 另外确认过坐标本身没问题：花括号 op 是 `486,349 29×468`、`720,232 31×253`、
> `875,183 10×97`，与 XML 的 EMU 换算完全一致。之前看着「跑到右边」，
> 纯粹是因为文字全缩在左边，视觉上把标尺抬偏了。

## 1.4.6 更新（读版式 lstStyle：艺术字、字号、行距一起修好）

**艺术字不见了 / 线的位置不对**，其实是同一个根因：**版式（slideLayout）里占位符的
`<a:lstStyle>` 从来没被读过**。之前只从版式继承「位置和大小」，字号、颜色、
文字描边、项目符号全用母版 `bodyStyle` 顶替。后果有三：

1. **艺术字变纯黑字**。第 20 页标题在版式里写的是
   `<a:ln w="12700">accent2 + shade 90%</a:ln>` + `<a:solidFill>FFFFFF</a:solidFill>`
   —— 白字配深色描边。我们只取了字号，所以画成黑字，描边整个消失。
2. **正文大一号，把线压住了**。第 39 页版式写的是 24pt，母版是 28pt。
   文字被放大 17%，行距跟着变大，`int hour, minute, second;` 往下挤，
   正好压到「特定的访问权限」和它的引线 —— 看起来就像「线的位置偏了」。
   其实线的坐标一直是对的（`815,234 288×215`，与 XML 完全一致）。
3. **行距本身也偏大**。`setLineSpacing` 的基准从 1.18 倍改成 1.0 倍
   （Android 的字体行高本来就 ≈1.17em，再乘 1.18 就成了 1.38em）。

**这一版做了什么**

- `parsePhGeom` 重写：每个占位符除了 `off/ext`，还解析 `<a:lstStyle>` 的
  `lvl1pPr..lvl9pPr`（字号 `sz`、粗体 `b`、`marL`、`buChar/buNone`、
  `defRPr` 里的填充色与 `<a:ln>` 描边）。
- 优先级：幻灯片自己的 run 属性 > 版式 lstStyle > 母版样式表。
  版式里**没写**的字段（比如第 13 页只写了颜色、没写字号）自动回落到母版，
  不会再把「没写」当成 18pt。
- 新增文字描边渲染：先用描边色把整段文字 `STROKE` 画一遍，再叠正常填充。
  描边宽度按 PowerPoint 的 `w`（总宽）换算成 Android 的 `strokeWidth`（半宽）。
- 顺带修掉 `</a:ln>` 在 `rPr` 里时被误标成「形状有描边」的问题。

验证（Robolectric 直接读解析结果，不靠截图）：

```
第20页 标题 43pt  txtCol=#ffffffff  lnW=1.72  lnC=#ff3c7379   ← 白字 + 深色描边
第39页 正文 41px（24pt，原 48px）                              ← 行距回到 PowerPoint 的量
第13页 色块 ff92d050 / ffffc000 / ff66ffcc 全部保留
```

## 1.4.5 更新（文本框变黑条：`<a:extLst>` 里的填充被当成真填充）

第 39 页「外部接口 / 边界 / 特定的访问权限」三个白底文本框，被画成了三个黑色实心矩形，
文字压在里面看不见。源文件里它们写的是无填充：

```xml
<a:noFill/><a:ln><a:noFill/></a:ln>
<a:extLst>
  <a:ext uri="{909E8E84-…}"><a14:hiddenFill><a:solidFill><a:srgbClr val="FFFFFF"/>…</a14:hiddenFill></a:ext>
  <a:ext uri="{91240B29-…}"><a14:hiddenLine w="9525"><a:solidFill><a:srgbClr val="000000"/>…</a14:hiddenLine></a:ext>
</a:extLst>
```

`<a:extLst>` 是「扩展容器」，`a14:hiddenFill` / `a14:hiddenLine` 存的是**不渲染**的
样式副本（PowerPoint 用它记住「这个框曾经是什么样」，好让下次恢复）。但它们的子标签
也叫 `a:solidFill` / `a:srgbClr`，和真实填充完全同名，解析器照着读，于是：

1. `hiddenFill` 把 `noFill` 改成白色实心；
2. 紧接着 `hiddenLine` 里的 `solidFill`（黑色）**又把填充色覆盖成黑色**；
3. 线宽在 `</a:ln>` 时早已被清零，所以只有填充、没有描边 → 纯黑条。

现在遇到 `<a:extLst>` 整块跳过（`skipSubtree`），不再读它内部任何标签。
这份课件里 **107 个形状、13 页** 属于「自身无填充但扩展容器里有实心色」，
之前都被不同程度地涂色，可能盖住下面的箭头、表格或文字 —— 这一版一并恢复。

## 1.4.4 更新（大括号画成方块 + 说明框文字溢出）

**① 大括号 / 方括号以前一律画成矩形**
`rightBrace` / `leftBrace` / `leftBracket` / `rightBracket` 没实现，落到「未知预设退回矩形」
的兜底分支。第13页色块条下面那个 `}` 本来是 rot=90° 横过来的括号，被画成了一个方框。
现在按 OOXML 的公式（`r = min(w,h)*adj1/200000`）在单位方框里构造：上下两端在左侧、
中间的尖在右侧；顺时针转 90° 之后就是「︸」，和 PowerPoint 一致。

**② 普通形状的字号被错误地继承了母版正文（28pt → 18pt）**
只有占位符才继承母版 `bodyStyle`；普通形状（`p:sp` 里没有 `p:ph`）在 PowerPoint 里
默认就是 18pt、无缩进、无项目符号。之前一律取 `bodyStyle` 一级样式，这份课件是 28pt，
于是第9页「一般形式为 / struct 结构体名 / { 成员表列 / } 变量名表列;」这个窄框里的
文字被撑大一倍，第四行压在框线上、第五行整个掉到框外。
现在普通形状按 18pt 排版（`pPr` 里写了 `marL` 的缩进照旧生效）。

装好后打开旧笔记会自动重画底图（`RENDER_VERSION` 5）。

## 1.4.3 更新（颜色与格式全丢：四处根因）

这一版把「PPT 只有黑白文字、色块和箭头全不见」彻底修掉，原因是四个互相独立的 bug：

**① 颜色判断用了 `>= 0`，而 ARGB 颜色永远是负数**
`colBase` / `refColor` 里存的是 `0xFFxxxxxx`，在 Int 里是负数，代码却用
`if (colBase >= 0)` 判断「这个颜色有效」。于是**每一个 srgbClr / schemeClr 都被当成无效丢弃**：
色块没有填充、线条没有颜色、文字退回默认黑。哨兵值改成 0 之后全部恢复。

**② 主题样式表根本没读进来**
`a:fmtScheme` 挂在 `a:themeElements` 下面，代码却直接找 `a:theme` 的子节点，
永远返回 null → `fillStyleLst` / `lnStyleLst` 全空 → 所有「没写颜色、
靠 `p:style` 的 fillRef / lnRef 取主题」的形状透明。
课件里箭头、大括号、色块边框都是这种写法，所以一起消失了。

**③ 行距凭空大一半**
1.4.2 为了保住空行，给**每个**段落的末尾都插了一个零宽字符并挂上默认字号，
整行行高被撑到 32pt，18pt 的代码行距变成 1.7 倍，内容溢出文本框，
`};` 和最后几行直接被挤出页面。现在零宽字符只加在**空段落**上。

**④ 第一段丢项目符号**
段落没写 `<a:pPr>` 时（课件第一段常常没有），字号/缩进/项目符号会沿用上一段，
一级圆点整段消失。现在每段开始都按第一级样式初始化（标题类占位符除外）。

验证方式：给项目加了 Robolectric 单元测试，直接调用真实的 `loadSlideArt()` 检查
每个形状的 fill / line / 文字色，不再靠截图猜。

## 1.4.2 更新（图片错位 + 正文压表格，两个解析 bug）

这一版修的是**解析器**，不是排版参数，所以影响面比看起来大：这份课件里 18 页有形状被错放、18 页有正文上移。

**① 图片和图形全堆到页面左上角**
`<a:ext uri="{...}">` 是「扩展容器」（a14:hiddenFill / hiddenLine 之类），没有 `cx/cy`。
它在 `p:spPr` 里**排在 `<a:xfrm>` 后面**，解析器却把它当几何尺寸读，把刚刚读到的 cx/cy 覆盖成 -1，
形状于是被判定成「这个框没有坐标」，掉进兜底逻辑：宽度取页宽的 84%、从左边 8% 处开始往下排。
第 21 页那张「1000 地址」表格图就是这么跑到页顶、盖住紫色色带和标题的。
现在只认**带 cx/cy / x/y 属性**的 off/ext，扩展容器一律忽略。

**② 空段落被整段丢掉，正文上移压在表格上**
PowerPoint 里「例如」和后面几行之间常夹着几个空段落（课件靠这些空行给表格让位），
以前 `</a:p>` 只在「这段有字」时才补换行，空段落等于不存在，后面的正文直接上移。
第 23 页两栏代码表压住「共用体与结构体的定义形式相似」就是这个原因。
现在空段落补一个零宽字符 + 换行，并按该段字号设行高，空行高度和 PowerPoint 一致。

装好后打开旧笔记会自动重画底图（`RENDER_VERSION` 3），约 30~60 秒，当前页先更新。

## 1.4.1 更新（旧笔记自动重画底图 + 三处排版修正）

这一版最要紧的一条：**升级后不用再删笔记重导入了**。

**1. 旧底图自动重画**

页面底图是导入那一刻栅格化存下来的，之后再怎么修渲染引擎，旧笔记看到的还是旧图 ——
这也是「明明说了修好，看着还是老样子」的根源（1.4.0 之前导入的 PPT 页，色块、箭头、
母版装饰根本没画进去）。现在 meta.json 里记了一个 `renderV`，打开笔记本时：

- 发现版本落后、且目录里还留着源 `.pptx`，就在后台用当前引擎把每页重画一遍；
- 只替换 `bg_*.png`，**笔迹文件一个字节不动**，批注不会丢；
- 正在看的那一页重画完立刻换上（`replaceBackground`，不清笔画、不跳视口、不清撤销栈）；
- 幻灯片尺寸被改过（重画出来和页面坐标系对不上）就跳过，宁可留旧图也不拉变形。

**2. 空占位符的提示语不再当正文画**

`双击此处添加文本` / `单击此处编辑母版文本样式` 这类 PowerPoint 编辑态提示，有些版本另存后会被
当成真文字写进 `slideN.xml`。现在按整句精确匹配丢掉，不会误伤正文。

**3. 普通形状不再继承母版的项目符号**

以前所有形状都套 `lvl1` 的圆点，于是图注色块上的「8B」变成「· 8B」。PowerPoint 里只有
占位符才继承正文项目符号，现在按这个规则来。

**4. 窄框里的短标签不再拆行**

「2B」「8B」这类两三个字符的标签，字体实际宽度比 PowerPoint 估算的多几个像素就会被折成
「2」+「B」两行。现在单行短标签会按需要放宽排版宽度（居中偏移同步回正），宁可略微溢出框。

## 1.3.3 更新（圈擦改成整笔删除）

**行为变了**：圈擦不再是「按圈的形状裁掉一块」，而是**圈到哪一笔就整笔删掉**。

- 判定用「有任何接触就算中」：采样点落在圈里，或者这一笔横着穿过圈的边界，都算

- 圈住一个字，那个字整笔消失，不会只剩半边笔画；圈里没有笔就不动手，不占一步撤销

保留了下来，只用于渲染那些旧轨迹；新操作不再产生这种轨迹。

## 1.3.2 更新（笔迹质量重做 + 圈擦）

**放大后笔迹「毛躁」的真因：一笔由几十个梯形拼起来**

以前一笔的画法是「每两个采样点之间画一个梯形」，再把几十个梯形塞进同一个 Path 填充。
问题是相邻梯形**并不共用边** —— 拐弯外侧留楔形缺口，内部则每条接缝都被抗锯齿处理一次，
放大 4 倍就成了一道道横穿笔迹的浅色「竹节纹」，两端还是被斜切的平头。
马克笔/荧光笔更明显：笔画越宽，缺口和接缝按比例越大。

我按同一套算法在 PC 上复刻了新旧两种画法做像素级对比（4 倍放大）：

| | 笔迹内部出现亮缝的列 | 内部最亮像素 |
|---|---|---|
| 旧（梯形拼接） | 98 / 1525 列 | 106（肉眼可见的灰线） |
| 新（单条轮廓） | **0 列** | 7（纯黑，只是抗锯齿） |

**现在的做法：一条闭合轮廓 + 样条采样**

- 采样点先用 **Catmull-Rom** 插值成真正过点的曲线（按曲率自适应细分：直的地方一步走完，
  弯的地方最多分 16 段），不再是折线
- 沿曲线左右各偏移半个线宽，得到**一条**闭合轮廓：左边界 → 末端圆头 → 右边界 → 起点圆头。
  内部没有边，接缝也就不存在；圆头并进轮廓，荧光笔不会在两端叠出深色圆斑
- 法线用前后两点的中心差分求，拐角处两侧共用同一条法线，轮廓天然连续

**顺带的好处**：所有已有笔迹不需要重画、不需要迁移数据 —— 改的是渲染，打开就是新的样子。

**圈擦（第 7 个工具）**

选中「圈擦」，随手画一个圈，松手即刻删掉圈到的笔（1.3.3 起为整笔删除，见下节）。

## 1.3.1 更新（解决「原大小就糊」——底图分辨率与屏幕对齐）

**为什么以前是「原大小糊、放大反而清楚」**

以前导入时按 1240px 宽把内容排一次版、存成一张位图。而屏幕宽 1600px、页面按 fit 只占 96%，
算下来 1240px 的图要拉到 1536 个物理像素上显示 —— **放大 1.24 倍，字当然是糊的**。
一旦手指再放大，画布会切到「矢量重渲染」路径（PPT/PDF 都保留了源文件），
按可见区域重新排版画一遍，于是又变清楚了。所以出现了「不放大反而糊」这种反直觉的现象。

**修法：让导入页的底图和屏幕宽度对齐**

- PPT / DOCX / TXT 的渲染宽度从 1240 提到 **1654**（与 PDF 一致）。1654 放到 1536 的显示宽度上是**缩小**，
  字边缘保持锐利；换更宽的屏也只是继续缩小，不够时再交给矢量重渲染兜底
- 页面位图分辨率与页面坐标系解耦：画布按目标矩形缩放绘制底图，以后换分辨率不会错位
- 切换矢量重渲染的阈值不再写死「fit 的 1.35 倍」，改成「底图开始被放大时」——
  换设备自动适配：底图够大就晚点切，底图小就早点切
- 顺带：**空白页的格线不再画进位图**，改成每帧现画，放大多少倍都是 1~2 个屏幕像素的实线

**书架的封面也糊：360px 的图拉到 750px**

封面缩略图以前固定 360px 宽，而书架两列布局在 1600px 屏上每张卡约 750px 宽 —— 又被放大了两倍。
现在封面宽度按屏幕算（屏宽的 0.5，夹在 560~960 之间），并且**打开书架时会自动把旧笔记的低清封面重画一次**
（只做一次，文件已经够大就跳过）。

**必须做的**：PPT 旧笔记要**删掉重新导入**——底图是导入那一刻画好的，旧文件不会自己变清晰。

## 1.3.0 更新（PPT 三处硬伤 + 跳转页码）

**1. PPT 放大不再糊：按视口重画，而不是放大位图**

PPT 页在导入时是「按 1240px 宽把文字排版画成一张图」，放大就是插值，字必然成马赛克。现在导入 pptx 时同样把源文件留一份（`src_<时间戳>.pptx`），放大超过 fit 的 1.35 倍后，只针对**当前可见区域**重新解析该页的形状（文字走 StaticLayout、图片用原始位图），在带缩放的 Canvas 上重画成瓦片：

- 文字是矢量排版的，3 倍、6 倍放大边缘依然锐利
- 瓦片 768px 切块、缩放按 0.5 倍量化、最多缓存 12 块（与 PDF 同一套机制）
- 解析结果（形状指令 + 图片位图）按页缓存一份，滑动时不重复读 zip
- 顺手修掉一个隐患：源文件以前用固定名 `src.pdf`，同一个笔记本导入第二个 PDF 会把第一个的高清源覆盖掉；现在带时间戳，互不干扰

**2. 文字溢出页面被裁半行：读 `normAutofit`**

PowerPoint 在「文字太多、自动缩小」时并不改字号，而是把缩小比例写进 `<a:bodyPr><a:normAutofit fontScale="62500" lnSpcReduction="20000"/>`。之前忽略了这个字段，于是 32pt 的文字按 100% 画出来，比实际大 60%，整段溢出到页面外，被页面边界裁掉半行（你截图里 `cout<<student1.name;` 就是这么没的）。

现在：

- `fontScale` 直接乘到每个 run 的字号上，`lnSpcReduction` 折算进行距
- 再叠一层兜底：如果排完还是超出文本框，按比例缩字号（最多缩 28%，缩太多说明框本身尺寸不对，宁可溢出也不缩成蚂蚁字）

**3. 表格跑到左上角压住标题：读 `graphicFrame` 的坐标**

`<a:off>/<a:ext>` 之前只对 `sp`/`pic` 生效，`graphicFrame`（表格、图表）的坐标从来没被读出来，所有表格都落到兜底的 `(0.06W, 20px)`，于是第 11 页那张表贴着页面左上角、把标题压成了只剩一个「结」字。

顺带把表格本身重做了：

- 列宽取 `a:gridCol`（不再均分）；行高取 `a:tr/@h` 与文字实际高度的较大值
- 支持 `gridSpan` 跨列（表头 "birthday" 盖住 month/day/year 那种）与 `hMerge`/`vMerge`
- 单元格字号/粗体/颜色/对齐、`tcPr` 内边距、`anchor` 垂直居中
- 表比框宽时整体等比缩小，不再从页面左边溢出去

**4. 跳转到任意页**

- 底部胶囊中间的「16 / 127」现在可以点，弹出页码输入框 + 拖动条
- 「更多」菜单里也有「跳转到指定页」入口
- 输入框只接受数字，超范围会标红、确定键禁用

## 1.2.1 更新（修放大清晰度与 PPT 排版）

**1. PDF 放大后不糊 —— 按视口从矢量源重渲染**

原来的做法是把 PDF 每页渲染成一张约 1654px 宽的位图，放大就是把这张图拉大，到 3 倍以上必然糊。现在导入 PDF 时会额外把源文件留一份（`src.pdf`），放大超过 1.35 倍后，画布只针对**当前可见区域**重新用 `PdfRenderer` 渲染成瓦片盖在底图上：

- 瓦片按 768px 切块，缩放按 0.5 倍量化，平移/轻微缩放命中缓存时零开销
- 每块按当前缩放渲染到屏幕像素密度，所以任意倍率下文字边缘都是锐利的
- 内存里最多留 14 块（约 30MB），随用随淘汰
- 拿走页面立即回收渲染器与瓦片

**2. 文字底图改用 PNG**

你截图里文字周围的毛边是 JPEG 的 8×8 DCT 振铃，不是分辨率不够。现在导入时抽样统计颜色数：文本/矢量页（颜色少）存 PNG，无损；照片/扫描件（颜色多）仍存 JPEG(q90)。文本页的 PNG 反而比 JPEG 更小。

**3. PPTX 排版错乱的根因：占位符几何继承**

这是这次最关键的一处。幻灯片里的标题、正文经常**不带自己的坐标**，位置大小是从版式（`slideLayout`）、母版（`slideMaster`）继承来的。之前的实现没解析这一层，所有占位符都落到同一个兜底坐标上 —— 于是标题和正文直接叠在一起，就是你看到的"内容重叠"。

现在按 自身 → 版式 → 母版 的顺序解析：

- 按 `p:ph type / idx` 匹配版式里的同名占位符取几何
- 标题字号从母版的 `titleStyle`（36pt），正文从 `bodyStyle` 各级（28/26/24pt）继承，不再统一退化成 18pt
- 解析 `p:grpSp` 分组变换（全篇 15 处分组），组内坐标按 `off/ext/chOff/chExt` 换算
- 项目符号按母版 `buChar` 生成（lvl1 `•`、lvl2 `▫`，空字符表示只缩进不显示符号）
- 段落缩进用 `marL`（LeadingMarginSpan）还原，代码块因此有了正确的左缩进
- 支持 `bodyPr anchor`（垂直居中 / 底对齐）和 `wrap="none"`（不折行）

## 已知限制

1. **Office 仍是"尽力保真"**：艺术字、SmartArt、图表（chart）、复杂表格边框、多栏排版、文本框旋转不会还原；嵌入的 SVG 图片不解析（只认 png/jpg 等位图）；Word 的自动编号/项目符号会丢失编号本身，只保留文字。
2. **PPT 的版式图形（母版上的色带、LOGO、装饰箭头）不会绘制**：只渲染幻灯片自身的形状。所以画面轮廓对了，但背景装饰会缺。
2. **PPTX 的整页预览图判定依赖命名**：文件名或描述里带 `preview` / `render` / `.png` 等特征才认定是预览图。如果某份 PPT 是"整页大图 + 文字说明"的设计，可能会被当成预览图而只显示图片。
3. **高清重渲染与底图分辨率只对重新导入的文件有效**：PDF 需要 1.2.1+ 导入、PPT 需要 1.3.1+ 导入（都要求当时保存了源文件）。旧笔记没有源文件，放大仍然只有那张位图 —— 删掉旧笔记重新导入一次即可。
4. **橡皮的局部擦除会让重绘变慢**：页面里存在擦除轨迹时，每帧要多一次离屏图层合成。笔迹上千的页面在高倍缩放下可能掉帧，整笔擦除模式没有这个开销。
5. **压感模拟只是近似**：真实压感笔完全不受影响；普通电容笔的速度模拟能做出粗细变化，但不如真压感自然。
6. **没有云同步**：备份是本地 zip，需要自己拷到网盘或电脑。要真同步得加账号体系和后端。
6. 页面尺寸固定 A4，导入内容按比例缩放，不做裁切。PDF 导出是 150dpi 基准的矢量，打印够用但不是印刷级。

## 操作说明

- **手指 / 笔都能写**：默认「手指可写」，单指画即书写；平移缩放请用**双指**。底部工具栏右侧可切到「手指平移」，此时只有笔（主动笔）能写。
- **写字时手掌会误触吗**：如果用的是主动式手写笔，笔画会自动忽略手指触点；如果是普通电容笔，系统无法区分，建议开启「手指平移」或垫手。
- 顶栏：返回、标题、撤销、重做、更多（插入空白页 / 适配屏幕 / 删除本页 / 导出 / 压感开关）
- 画布底部胶囊：翻页；点中间的「当前页 / 总页数」可直接输入页码跳转
- 删除页面后，底部会出现「已删除第 N 页 · 撤销」，5 秒内点撤销即可恢复
- 导出：编辑器「更多」里可导出本页 PNG / 整本 PDF / 打包备份；书架长按笔记本菜单里也有整本导出与备份
- 恢复备份：书架右上角「恢复备份」，选一个 `.noteink.zip`，会还原成一个新笔记本
- 橡皮模式：选中橡皮后工具栏底部会多出「整笔 / 局部」两个选项

## 技术栈

Kotlin 1.9.24 · Jetpack Compose (BOM 2024.06, Material 3) · AGP 8.5.2 / Gradle 8.7 · 画布为自绘 `View`（`AndroidView` 嵌入 Compose），PDF 用系统 `PdfRenderer`，无第三方运行时依赖。

## 隐私

- **不联网**：清单里没有声明 `INTERNET` 权限，系统层面就无法发起网络请求
- **无第三方 SDK**：运行时依赖只有 AndroidX / Jetpack Compose，没有统计、广告、崩溃上报库
- **数据在应用私有目录**：所有笔记存在 `filesDir` 下，其他应用读不到，卸载即清除
- **唯一对外组件**是启动页 Activity，没有 Service / Receiver / ContentProvider
